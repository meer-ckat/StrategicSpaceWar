# 함선 설계도 작성법

파일 하나 = 함선 한 척. 파일 이름이 곧 def 이름이다 (`destroyer.json` → `Ship.shipDefName = "destroyer"`).

배는 **1 m 정수 격자**에 물건을 놓아서 짓는다. 프리팹도 스프라이트 파일도 없다 —
이 JSON 하나가 함선의 전부다.

## 형식

```json
{
  "defName": "destroyer",
  "basedOn": "destroyer",
  "massPerPlate": 420,
  "drag": 0.3,
  "angleAccel": 20,
  "placements": [
    { "def": "Armor mk5", "col": 0, "row": 0, "rot": 0, "mountCol": -1, "mountRow": -1 }
  ]
}
```

### 최상위 키

| 키 | 뜻 |
|---|---|
| `defName` | 파일 이름과 맞춘다 |
| `basedOn` | 원본 설계도 이름. **자기 자신을 적는다.** 손상 저장본이 원본을 찾는 끈이다 |
| `hullSkin` | 함선 그림 PNG 파일명 (선택). 없으면 판이 단색으로 나온다 |
| `massPerPlate` | 판 한 장의 질량(kg). 총질량 = 판 수 × 이 값 |
| `drag` | 항력. 종단속도 = 추력 / (질량 × drag) |
| `angleAccel` | 선회 각가속. **질량과 무관하다** |
| `angleDrag` / `angleBrake` | 회전 감쇠·제동 |
| `leakRate` / `doorRate` | 공기가 새는 속도 / 문 여닫는 속도 |
| `crews` | 승무원 수 |
| `FightDistance` / `DetectionDistance` | AI가 유지하려는 거리 / 탐지 거리 |
| `breakawaySpeed` | 파단 조각이 튕겨 나가는 속도 |

**모르는 키를 하나라도 쓰면 그 배가 통째로 안 실린다.** 오타가 조용히 기본값으로 묻히는
것보다 낫다는 판단이다. 위 목록에 없는 키는 쓰지 마라.

### 배치 키 (`placements`)

| 키 | 뜻 | 생략하면 |
|---|---|---|
| `def` | 물건 이름. 아래 목록에서만 | 필수 |
| `col` | 칸 좌표 X. **클수록 뱃머리 쪽** | 필수 |
| `row` | 칸 좌표 Y. **클수록 아래쪽** | 필수 |
| `rot` | 회전(도). **수직에서 잰다** — 아래 참고 | 0 |
| `size` | 콜라이더 크기 `{x,y}`. def 값을 이긴다 | def 값 |
| `offset` | 콜라이더만 미는 값 `{x,y}`. **오브젝트는 안 움직인다** | 0 |
| `hp` | 남은 체력 비율 0~1. 손상 저장본에만 쓴다 | 1 |
| `mountCol` / `mountRow` | **모듈이 얹힐 판의 칸 좌표** | -1 (판 자신) |

## 두 종류뿐이다 — 판과 모듈

**판** (`Armor …`, `Ballistic Door`, `Glass`) — 격자에 도장을 찍는다. 배의 뼈대이자 외피다.
`mountCol`/`mountRow`는 `-1`.

**모듈** (포·엔진·탄약고·원자로) — 격자를 차지하지 않는다. **반드시 어느 판 위에 얹힌다.**
`mountCol`/`mountRow`에 그 판의 칸 좌표를 적는다.

모듈이 얹힌 판이 부서지면 모듈도 같이 죽고, 그 판이 잔해로 떨어져 나가면 모듈도 같이
날아간다. 별도 코드가 없다 — 이 부모 자식 관계 하나에서 전부 나온다.

**모듈의 `mountCol`/`mountRow`가 빈 칸을 가리키면 그 모듈은 안 생긴다.**

## 쓸 수 있는 def

### 장갑판

| def | RHA | HP/m² | 두께 | 쓰는 곳 |
|---|---|---|---|---|
| `Armor mk3` | 140 | 180 | 0.35 | 정찰함, 폐선 |
| `Armor mk4` | 190 | 240 | 0.42 | 프리깃 |
| `Armor mk5` | 250 | 300 | 0.50 | 구축함 (기준선) |
| `Armor mk6` | 330 | 400 | 0.62 | 순양함 |
| `Lance Armor` | 400 | 100000 | 0.50 | 충각 끝. 사실상 안 부서진다 |
| `Ballistic Door` | 10 | 500 | — | 문. 방과 방을 잇는다 |
| `Glass` | 1 | 10 | — | 창. 총알이 그냥 지나간다 |
| `Rock` | — | — | — | 운석 전용 |
| `Mirror` | — | — | — | 반사 껍질 전용 |

### 포탑 (모듈)

| def | 탄 | RPM | 선회 | 사각 | HP | 성격 |
|---|---|---|---|---|---|---|
| `pd20` | 20mm | 900 | 140°/s | 5° | 90 | 근접방어. 빠르게 돌고 많이 쏜다 |
| `m7` | 105mm | 300 | 30 | 2° | 250 | 표준 주포 |
| `m9` | 155mm | 90 | 16 | 1.5° | 420 | 중주포 |
| `rail` | Railgun Bullet | 20 | 8 | 0.8° | 500 | 레일건. 단발 저격 |

### 그 밖의 모듈

| def | 하는 일 | HP | 죽으면 |
|---|---|---|---|
| `SuperDuper Engine` | 추력 100 kN | 100 | 추력이 그만큼 사라진다 |
| `Reactor` | 전력 공급 | 90 | **유폭** (blast 1600) |
| `Magazine` | 탄약고 | 60 | **유폭** (blast 3200) |

**원자로가 하나도 없으면 조타·조준이 멈춘다.** 전력이 필요한 배면 최소 하나, 웬만하면
떨어진 자리에 둘 이상 놓아라.

탄약고와 원자로는 **맞으면 터진다.** 어디에 뒀느냐가 곧 그 배의 약점이다 — 중앙 깊숙이
두면 잘 안 맞고, 외피 가까이 두면 한 발에 배가 갈린다. 그게 의도된 설계다.

## 밀폐 — 제일 자주 틀리는 것

배 안이 **판으로 완전히 둘러싸여야** 실내가 된다. 테두리에서 4방향으로 비어 있는 칸을 타고
들어올 수 있으면 그 칸은 우주다.

외곽에 한 칸이라도 구멍이 있으면 **배 전체가 우주로 판정되고 공기가 없다.** 승무원이
바로 죽는다.

- 외곽선은 끊기지 말 것
- 대각선만 맞닿은 것은 안 통한다 (공기는 4방향으로만 샌다)
- 안쪽 빈 칸이 곧 방이다. 문(`Ballistic Door`)으로 방을 나눈다

## 구조 연결성

선체가 이어져 있는지는 **8방향**으로 본다(대각선 포함). 그래서 계단식으로 놓은 판도
한 덩어리다. 이어짐이 끊기면 그 순간 배가 갈라져 잔해로 날아간다.

밀폐(4방향)와 구조(8방향)가 **정반대 규칙**이라는 점만 기억하면 된다.

## 경사판

`rot`은 **수직에서 잰 각도**다. 판의 긴 축이 세로에서 시작하기 때문이다.

부호: 오른쪽으로 갈수록 **내려가면 양수**, 올라가면 음수.

| 경사 | `rot` | `size` | `offset` |
|---|---|---|---|
| 45° (1칸 가고 1칸) | ±45 | `{x:1, y:1.4142136}` | 없음 |
| 63.4° (2칸 가고 1칸) | ±63.43495 | `{x:1, y:1.1180340}` | `{x:0, y:±0.25}` 번갈아 |

**2:1 경사는 칸마다 판 한 장씩** 놓고 `offset.y`를 `+0.25`, `-0.25`로 번갈아 준다.
그래야 두 판이 한 직선 위에 이어 붙는다.

판 하나로 두 칸을 덮으면 **옆 칸이 격자에서 비어서 공기가 샌다.** 반드시 칸마다 한 장.

`offset`은 콜라이더만 민다. 격자 칸은 `col`/`row`가 정하고 안 움직인다.

## 예시 — 최소 함선

```json
{
  "defName": "tiny",
  "basedOn": "tiny",
  "massPerPlate": 300,
  "drag": 0.3,
  "angleAccel": 30,
  "crews": 1,
  "placements": [
    { "def": "Armor mk3", "col": 0, "row": 0, "mountCol": -1, "mountRow": -1 },
    { "def": "Armor mk3", "col": 1, "row": 0, "mountCol": -1, "mountRow": -1 },
    { "def": "Armor mk3", "col": 2, "row": 0, "mountCol": -1, "mountRow": -1 },
    { "def": "Armor mk3", "col": 0, "row": 1, "mountCol": -1, "mountRow": -1 },
    { "def": "Armor mk3", "col": 2, "row": 1, "mountCol": -1, "mountRow": -1 },
    { "def": "Armor mk3", "col": 0, "row": 2, "mountCol": -1, "mountRow": -1 },
    { "def": "Armor mk3", "col": 1, "row": 2, "mountCol": -1, "mountRow": -1 },
    { "def": "Armor mk3", "col": 2, "row": 2, "mountCol": -1, "mountRow": -1 },

    { "def": "Reactor", "col": 1, "row": 0, "mountCol": 1, "mountRow": 0 },
    { "def": "SuperDuper Engine", "col": 0, "row": 1, "mountCol": 0, "mountRow": 1 },
    { "def": "pd20", "col": 2, "row": 1, "mountCol": 2, "mountRow": 1 }
  ]
}
```

가운데 칸 `(1,1)`이 비어 있고 사방이 막혀 실내가 된다. 모듈 셋은 각자 판 위에 얹혔다.

## 고칠 때

`Tools > Defs > Reload`. 함선은 `Awake`에서 읽으므로 플레이를 다시 시작해야 한다.

## AI에게 그대로 주는 프롬프트

```
SUPERRADIANCE(2D 사이드뷰 우주 함선 시뮬레이션)의 함선 설계도 JSON을 써라.
사진을 주면 그 실루엣을 1 m 정수 격자로 옮긴다.

출력은 JSON 하나뿐. 설명 문장을 섞지 마라.

형식:
{
  "defName": "<파일이름>",
  "basedOn": "<같은 이름>",
  "massPerPlate": 350,
  "drag": 0.3,
  "angleAccel": 24,
  "angleDrag": 0.5,
  "angleBrake": 10,
  "leakRate": 2,
  "doorRate": 1,
  "crews": 3,
  "FightDistance": 180,
  "DetectionDistance": 300,
  "breakawaySpeed": 2,
  "placements": [
    { "def": "Armor mk4", "col": 0, "row": 0, "rot": 0, "mountCol": -1, "mountRow": -1 }
  ]
}

위 최상위 키 말고 다른 키를 쓰면 배가 안 실린다. 새 키를 만들지 마라.

좌표:
- col은 클수록 뱃머리(오른쪽), row는 클수록 아래.
- 둘 다 정수. 음수도 된다.
- 한 칸에 판은 하나만. 겹치면 안 된다.

판(격자를 차지하는 것) — mountCol/mountRow는 -1:
  Armor mk3 (얇음) / Armor mk4 / Armor mk5 / Armor mk6 (두꺼움)
  Ballistic Door (문) / Glass (창)

모듈(판 위에 얹히는 것) — mountCol/mountRow에 그 판의 col,row를 적는다:
  포탑:   pd20 (근접방어, 연사) / m7 (표준 주포) / m9 (중주포) / rail (레일건 저격)
  기타:   SuperDuper Engine (추력 100kN) / Reactor (전력) / Magazine (탄약고)

규칙:
- 모듈의 mountCol/mountRow는 반드시 판이 있는 칸이어야 한다. 빈 칸이면 그 모듈은 안 생긴다.
- 모듈은 자기 col/row도 함께 적는다. 보통 mount와 같은 칸이거나 그 바로 바깥이다.
- 외곽선이 한 칸도 끊기면 안 된다. 4방향으로 바깥과 이어지면 그 칸은 우주가 되고,
  구멍이 하나라도 있으면 배 전체에 공기가 없어 승무원이 즉사한다.
- 안쪽 빈 칸이 방이다. 방이 둘 이상이면 Ballistic Door로 이어라.
- 선체는 8방향(대각선 포함)으로 이어져 있어야 한 덩어리다. 끊기면 그 자리에서 갈라진다.
- Reactor를 최소 하나. 없으면 조타와 조준이 멈춘다.
- Reactor와 Magazine은 맞으면 유폭한다. 외피에서 떨어진 안쪽에 둬라.
- 엔진은 배의 뒤쪽(col이 작은 쪽) 끝에 붙인다.

경사판(선택):
- rot은 수직에서 잰 각도다. 오른쪽으로 내려가면 양수, 올라가면 음수.
- 45도: "rot": 45, "size": {"x":1,"y":1.4142136}
- 63.4도(2칸당 1칸): "rot": 63.43495, "size": {"x":1,"y":1.1180340},
  "offset": {"x":0,"y":0.25} 와 {"x":0,"y":-0.25} 를 칸마다 번갈아.
- 경사도 칸마다 판 한 장씩. 한 장으로 두 칸을 덮으면 공기가 샌다.

크기 기준: 정찰함 24x9칸 / 프리깃 35x12 / 구축함 56x18 / 순양함 65x18.

주제: <여기에 무엇을 만들지 쓴다>
파일 이름: <여기에 파일 이름>
```

프롬프트에서 `massPerPlate`는 장갑 두께에 맞춰라 — mk3이면 300, mk4 350, mk5 420, mk6 520.
