  # 대사 대본 작성법

  파일 하나 = 대본 하나. 파일 이름이 곧 대본 이름이다 (`prologue.json` → `Play("prologue")`).
  없는 이름을 부르면 조용히 아무 일도 안 일어난다 — 대사를 안 쓴 사건 때문에 게임이 멈추지 않는다.

  ## 형식

  ```json
  {
    "defName": "prologue",
    "pickOne": false,
    "cooldown": 0,
    "lines": [
      {
        "message": "관제, 뭔가 잡힙니다. <color=yellow>조난 신호가 아닙니다.</color>",
        "author": "전술",
        "duration": 5,
        "intensity": 0.8,
        "wait": 0
      }
    ]
  }
  ```

  **파일 단위**

  | 키 | 뜻 | 생략하면 |
  |---|---|---|
  | `pickOne` | 참이면 `lines` 중 **한 줄만** 고른다 (대본이 아니라 변형 목록) | false |
  | `cooldown` | 이 초 안에는 같은 대본이 다시 안 나온다 | 0 (제한 없음) |

  **줄 단위 (`lines`)**

  | 키 | 뜻 | 생략하면 |
  |---|---|---|
  | `message` | 대사 본문. `<color=...>` `<b>` `<i>` 사용 가능 | 그 줄은 무시된다 |
  | `author` | 대사 아래 작게 붙는 화자. 빈 문자열이면 안 나온다 | 화자 없음 |
  | `duration` | 이 줄이 **화면에 머무는** 초 | 4 |
  | `intensity` | 등장 충격 세기. 아래 참고 | 1 |
  | `wait` | **다음 줄이 나올 때까지의** 초 (`pickOne`이면 안 쓴다) | 자동 (아래 참고) |

  `defName`은 기록용이라 파일 이름과 맞춰만 두면 된다. 실제로 찾는 건 파일 이름이다.

  ## 이야기 대본과 사건 대본

  **이야기 대본** (`prologue`, `battle-won`) — `pickOne` 없음. 줄이 순서대로 이어지는 한 장면이다.

  **사건 대본** (`detonated-enemy`, `hull-split-ally`) — `pickOne: true` + `cooldown`.
  유폭이 한 전투에 스무 번 나는데 매번 같은 문장이면 두 번째부터는 글자가 아니라 벽지다.
  줄을 여러 개 써 두면 그중 하나가 나온다. `cooldown`은 필수다 — 유폭·선체 절단은 한 틱에
  여러 번 날 수 있고, 없으면 화면이 대사로 덮인다.

  ## 타이밍 — `duration`과 `wait`은 다른 일을 한다

  - `duration` = 이 줄이 얼마나 오래 떠 있나
  - `wait` = 다음 줄이 얼마나 빨리 오나

  **둘이 다르기 때문에 통신이 겹친다.** `wait`이 `duration`보다 짧으면 앞줄이 아직 떠 있는 채로
  다음 줄이 올라오고, 오래된 줄은 위로 밀리며 흐려진다.

  `wait`을 0으로 두면 자동으로 **타이핑이 끝나는 시간 + 0.6초**가 된다. 보통은 이걸로 충분하다.

  - 타이핑 속도는 초당 42자. 100자짜리 대사 ≈ 2.4초. **한국어는 같은 뜻을 절반쯤의 글자로
    쓰므로 타이핑이 빨리 끝난다** - `wait: 0`으로 두면 영어 대본보다 줄이 촘촘하게 온다.
  - `duration`이 타이핑 시간보다 짧으면 자동으로 늘어난다 (타이핑 시간 + 0.5초가 하한).
  - 뜸을 들이고 싶으면 `wait`을 크게 (`"wait": 3`).
  - 몰아치게 하려면 `wait`을 작게 (`"wait": 0.3`).
  - 화면에는 동시에 최대 5줄. 넘으면 오래된 줄부터 밀려 나간다.

  ## `intensity`

  등장할 때의 충격 세기. 위치 튐, 떨림, 화자 이름 부풀기가 전부 이 값에 비례한다.

  | 값 | 느낌 |
  |---|---|
  | 0.5 | 시스템 로그, 배경 안내 |
  | 0.8 ~ 1.0 | 평범한 교신 |
  | 1.4 이상 | **화면 전체가 흔들린다.** 결정적인 대사에만 |
  | 2.0 | 신호 두절, 격침 보고 |

  1.4를 남발하면 아무것도 안 흔든 것과 같아진다.

  ## 치환

  `{0}`은 게임이 넘기는 값으로 바뀐다. 함선 이름 같은 것.

  ```json
  { "message": "<color=red>{0}</color> 응답 없음.", "author": "통신", "duration": 3 }
  ```

  ## 게임이 알아서 부르는 이름

  아래 이름으로 파일을 만들어 두면 해당 사건에 자동으로 재생된다. 없으면 그 사건엔 대사가 없다.

  사건 대본은 **팀별 이름을 먼저 찾고, 없으면 공용으로 내려간다.** `detonated-enemy.json`이
  없으면 `detonated.json`을 쓴다. 그래서 팀에 따라 말이 달라져야 하는 사건만 두 벌 쓰면 된다.

  | 파일 | 언제 | `{0}` |
  |---|---|---|
  | `prologue.json` | 시작할 때 (인스펙터 `openingScript`) | — |
  | `battle-won.json` | 전투 승리 | — |
  | `battle-lost.json` | 전투 패배 | — |
  | `ship-finished-{팀}.json` | 함선이 전투불능 | 함선 이름 |
  | `detonated-{팀}.json` | 탄약고·원자로 유폭 | 모듈 이름 |
  | `hull-split-{팀}.json` | 선체가 갈라져 조각이 떨어짐 | 함선 이름 |
  | `crew-lost-{팀}.json` | 승무원 전멸 (전 구역 감압) | 함선 이름 |
  | `sector-entered-{번호}.json` | 그 구역에 들어설 때 (1부터) | 구역 번호 |
  | `sector-cleared-{번호}.json` | 그 구역을 이겼을 때 | 구역 번호 |

  `{팀}`은 `enemy` / `ally` / `neutral`. 접미사 없는 파일이 공용 폴백이다.

  **횟수 접미사** — 전투 사건 넷(`ship-finished`, `detonated`, `hull-split`, `crew-lost`)은
  팀 뒤에 **이 런에서 몇 번째인가**를 붙인 파일을 먼저 찾는다:

  ```
  ship-finished-enemy-1.json   이 런의 첫 적함 격파. 있으면 그때 한 번만 나온다
  ship-finished-enemy-5.json   다섯 번째 격파
  ship-finished-enemy.json     그 외 전부 (pickOne 변형 목록)
  ```

  찾는 순서는 `키-팀-횟수` → `키-팀` → `키`. 횟수 파일은 이야기용(pickOne 없음),
  팀 파일은 변형 목록(pickOne)으로 쓰는 것이 결이 맞다. 구역 사건은 팀 대신
  번호로 갈리고(`sector-entered-3` = 3구역), 접미사 없는 공용 폴백은 같다.

  죽어서 같은 구역을 다시 열면 `sector-entered`가 또 적힌다 — "몇 번째 시도"도
  사건 횟수로 셀 수 있다는 뜻이다. 조건이 더 필요하면 코드 쪽 `RunLog.Count(종류, 팀)`을
  읽으면 된다.

  ## 고칠 때

  대본은 한 번 읽고 캐시된다. 에디터에서 JSON을 고쳤으면 플레이를 다시 시작하거나
  `StoryScriptManager.ReloadScripts()`를 부를 것.

  ## AI에게 그대로 주는 프롬프트

  ```
  SUPERRADIANCE(우주 함선 시뮬레이션 로그라이크)의 대사 JSON을 써라.

  형식:
  {
    "defName": "<파일이름>",
    "lines": [
      { "message": "...", "author": "...", "duration": 5, "intensity": 1.0, "wait": 0 }
    ]
  }

  규칙:
  - 게임 내 표시 언어는 한국어다. message와 author는 **한국어로** 써라.
  - message: 대사 본문. <color=yellow> <color=red> <color=grey> <b> <i> 사용 가능.
    강조할 구절만 색을 입히고, 한 줄 전체를 칠하지 마라.
  - author: 화자 이름. 함내 배치는
    함장 / 전술 / 포술 / 기관 / 통신 / 조타,
    함외는 아트리아 관제 / 함대사령부 / 시스템. 화자가 없으면 빈 문자열.
  - **`{0}` 뒤에 조사를 붙이지 마라.** 함선 이름의 받침에 따라 은/는, 이/가가 갈리는데
    치환은 그걸 모른다. `{0} 대열 이탈.`처럼 명사로 끊어라 - 무전 말투와도 맞는다.
  - duration: 화면에 머무는 초. 짧은 대사 3, 보통 5, 긴 설명 6~7.
  - intensity: 0.5 시스템 로그 / 0.8~1.0 평범한 교신 / 1.4 이상은 화면이 흔들리므로
    대본당 두세 줄만 / 2.0 신호 두절 같은 결정적 순간.
  - wait: 다음 줄까지의 초. 0이면 자동(타이핑 끝 + 0.6초)이고 앞줄과 자연스럽게 겹친다.
    뜸을 들일 자리만 2~4를 명시하고, 몰아칠 자리는 0.3.
  - 한 줄은 120자를 넘기지 마라. 길면 두 줄로 쪼개라.
  - 화면에 동시에 5줄까지만 뜬다.

  세계관:
  아트리아 공화국 대 변경, 12년째 전쟁. 블랙홀 시설을 반사 껍질로 감싸 초복사(superradiance)로
  증폭하는 무기가 있고, 그 시설은 원래 공화국 에너지 시설이었으며 무기 설계도 공화국 연구였다.
  플레이어는 아트리아 함장이고, 죽으면 다음엔 다른 함장이 온다.
  말투는 군용 무전. 짧고, 감정을 억누르고, 설명하지 않는다.

  주제: <여기에 무엇에 대한 대본인지 쓴다>
  파일 이름: <여기에 파일 이름>
  ```

  ## 연출 (cue)

  줄마다 `cue` 배열을 달면 **그 줄이 화면에 뜨는 순간** 같이 돈다. 대사와 연출을 같은
  파일에 적는 것이 요점이다 — 두 파일에 나뉘어 있으면 대사 한 줄을 옮길 때 반드시 어긋난다.

  ```json
  {
    "message": "<color=red>적함 포문 개방.</color>",
    "author": "전술",
    "duration": 3,
    "cue": [ { "act": "aimAt", "name": "창 1", "at": "player" } ]
  }
  ```

  ### 대상 (`name`)

  - `spawn`이 붙인 컷신 배의 이름.
  - **`player`는 예약어**로 지금 플레이어가 모는 배다. 처음 쓰는 순간 컷신이 조종간을
    넘겨받고(입력이 잠시 꺼진다), 컷신이 끝나면 그대로 돌려준다 — 지워지지 않는다.

  ### 지시 (`act`)

  | act | 하는 일 | 읽는 필드 |
  |-----|---------|-----------|
  | `spawn` | 컷신 배를 띄운다 | `name` `ship` `team` `x` `y` `facing` |
  | `despawn` | 그 배만 먼저 치운다 | `name` |
  | `moveTo` | 그 점으로 간다 | `name` + (`at` 또는 `x` `y`) |
  | `face` | 함체를 그 각도로 돌린다 | `name` + (`at` 또는 `x`=각도) |
  | `unface` | 각도 지시를 놓는다 (다시 진행 방향) | `name` |
  | `aimAt` | 포탑이 그 점을 겨눈다 | `name` + (`at` 또는 `x` `y`) |
  | `hold` | 조준은 하되 안 쏜다 | `name` |
  | `release` | `hold`를 푼다 | `name` |
  | `fire` | 방아쇠 없이 쏜다 | `name` |
  | `ceasefire` | `fire`를 푼다 | `name` |
  | `boost` / `unboost` | 부스터 | `name` |
  | `detonate` | 원자로를 터뜨린다 (없으면 탄약고) | `name` |
  | `look` | 카메라가 잡는다 | `name` + (`at`), 선택: `zoom`, `size` |
  | `engage` | 구역 대본 전용. 이 줄부터 캠페인이 적을 소환한다 (안 쓰면 대본이 끝나거나 45초 뒤) | — |
  | `camera` | 카메라 damp | `x`=이동, `y`=줌 |

  ### 알아 둘 것

  - `at`은 좌표 대신 **이름**으로 대상을 준다. 플레이어 좌표는 대본을 쓰는 시점에 알 수
    없으므로 이름으로만 가리킬 수 있다.
  - `team`은 `Ally` / `Enemy` / `Neutral`. 비면 `Enemy`. `facing`이 음수면 좌우 반전이다.
  - `look`은 `name` 하나면 그 배를 따라가고, `at`까지 주면 **둘 다 화면에 담는다**(거리에
    따라 줌이 벌어진다). `{ "act": "look" }`만 적으면 카메라를 놓는다.
  - `look.size`는 화면 세로 절반의 월드 크기다. `size: 60`이면 세로 120m를 본다.
    단독 함선 샷에서 이전 전체 구도의 줌을 물려받지 않으려면 명시한다. `size`가 양수이면
    두 대상 거리 계산보다 우선한다. 생략하면 기존 방식(`zoom`은 거리 배율)을 유지한다.
  - `camera`의 두 값은 SmoothDamp의 시간 상수라 **작을수록 빠르다.** `0`이면 그 프레임에
    딱 붙는다 — 장면이 바뀌는 자리에서 쓴다. 컷신이 끝나면 인스펙터 값으로 돌아간다.
  - 이동과 줌 모두 컷신에서는 실제 시간 기준으로 보간한다. 큰 이동은 `camera: x=4, y=4`
    정도에서 시작하고 한 구도를 12초 이상 유지해 볼 것. 4는 도착 시간이 아니라 감쇠 시간이다.
  - 구역 대본은 마지막 대사가 사라질 시간을 기다린 뒤 빈 줄의 `cue`에 `endCut`을 넣는다.
    임시 함선이 제거되고 조종권이 복구된다. Aim 카메라는 3초 동안 원래 조준 구도로 돌아간다.
    현재 Campaign의 대본 대기 상한은 90초(시뮬레이션 시간)다.
  - `hold`가 `fire`보다 세다. 둘 다 켜면 안 쏜다.
  - `aimAt`에서 대상을 못 찾으면 조준을 놓는다 — 그러면 포탑이 평소대로 가장 가까운 적을
    잡는다. `{ "act": "aimAt", "name": "창 1" }`처럼 `at`도 좌표도 안 주면 그 길로 간다.
  - `detonate`는 시뮬레이션의 유폭과 **같은 길**을 탄다. 컷신 전용 폭발이 따로 없어서
    화면에 나오는 그림이 실제 전투와 같다.

  **컷신 배는 캠페인의 배가 아니다.** 여는 대본이 화면에서 다 사라지면 전부 치우고 1구역이
  열린다. 그때까지 진짜 전투는 시작되지 않는다 — 씬의 Campaign에서 `waitForCutscene`을
  켜 두어야 그 순서가 성립한다.

  모르는 `act`나 없는 `name`은 경고만 찍고 넘어간다. 오타 하나로 컷신이 통째로 멈추면
  고치는 사람이 원인을 못 찾는다.

  `pickOne` 대본에는 연출이 안 붙는다 — 사건 대사는 한 줄짜리 변형 목록이라 연출을 걸
  자리가 아니다.
