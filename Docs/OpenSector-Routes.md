# 오픈섹터 항로 설계 — 정보·항로 유형·자원 (오너, 2026-09-13)

이 문서는 오너가 낸 설계 원문이고, 마지막 §9만 Claude가 코드와 대조해 붙인 것이다.
상위 문서는 `Docs/OpenSector-Report.md`(채택 이유·레퍼런스·PMI)이고 여기는 그중 "무엇을 고르게 할 것인가"만 다룬다.

## 1. 핵심 설계

오픈섹터 목적:

**탐험 → 정보 획득 → 항로 선택 → 필요한 자원을 남기도록 싸움 → 손상과 보급을 다음 구역까지 이월**

이 게임만 가능한 연결이다. 일반 오픈월드처럼 상자 열기가 아니다. 함선 상태가 탐험 목표와 **사격 위치**까지 바꾼다.

## 2. 다른 게임에서 가져올 원리

### Outer Wilds — 지식이 진행도

보상 대부분이 장비·경험치가 아니라 지식이다. 알아낸 세계 규칙이 다음 행동을 가능하게 한다. 퀘스트 마커 없이 호기심으로 이동하게 설계됐다.

적용:

- 단순 설정 문서 지급은 약하다.
- "B 항로 순찰은 부스터 방출을 추적한다"처럼 **행동을 바꾸는** 정보가 필요하다.
- 정보 획득 전후로 플레이 방법이 달라져야 한다.

### Death Stranding — 목적지보다 경로가 게임

직선은 위험할 수 있다. 지형·적·화물·장비를 보고 경로를 정한다. 장비도 경로 특성에 맞춰 고른다.

적용:

- 같은 항로도 **현재 함선 상태**에 따라 가치가 달라야 한다.
- 엔진 손상 함선은 넓고 안전한 항로.
- 탄약 부족 함선은 수송선 항로.
- 멀쩡한 함선은 위험하지만 노획 많은 항로.

### Subnautica — 자원이 새 탐색 범위를 연다

제작 자원이 숫자 축적보다 산소·수심·이동 수단을 열어 더 깊은 지역에 가게 한다. 라디오 신호가 샌드박스에 느슨한 방향을 준다.

적용 — 자원 종류보다 자원이 복원하는 **능력**이 중요하다.

| 자원 | 여는 것 |
|---|---|
| PROP | 이동 범위 |
| MUN | 교전 가능 횟수 |
| MTRL | 손상된 기능 복구 |
| RSCH | 다음 런 함선 선택권 |

## 3. 항로 정보 3축

모든 정보를 한 장소에서 주면 탐험 한 번으로 끝난다. 정보원을 나눈다.

| 탐색 장소 | 즉시 보상 | 얻는 정보 | 위험 |
|---|---|---|---|
| 교전 흔적 | 소량 MTRL·MUN | A/B 적 밀도 | 매복 가능 |
| 폐기 보급소 | PROP·MUN | A/B 보급 가능성 | 접근 시 추격대가 위치 탐지 |
| 항법 중계기 | 점프 앵커 | A/B 엄폐·거리 | 물질 보상 없음 |
| 적 수송선 | 대량 PROP·MUN | 다음 적 편성 일부 | 실제 교전 필요 |
| 기항지 | 정비 | 출구 목적지 이름 | 큰 우회 |

지도에 수집 개수를 안 쓴다. "정보 2/3" 같은 표시도 없다. 체크리스트 방지.

정보 표현도 정확한 숫자보다 비교형을 유지한다.

- 적: 적음 / 비슷 / 많음
- 보급: 희박 / 비슷 / 풍부
- 엄폐: 희박 / 비슷 / 밀집
- 특이사항: 추격 활동 / 정비 가능 / 수송선 관측

## 4. 항로 유형

각 항로는 최소 장점 하나, 비용 하나를 갖는다.

| 항로 | 장점 | 비용 |
|---|---|---|
| 안전 항로 | 적 적음 | 보급·노획 적음, 거리 김 |
| 수송 항로 | PROP·MUN 풍부 | 호위 전대, 개활지 |
| 잔해 항로 | MTRL·엄폐 풍부 | 매복, 충돌 위험 |
| 군사 항로 | RSCH·고급 노획 | 강한 적, 영구손상 위험 |
| 은폐 항로 | 추격 회피 쉬움 | 점프 앵커 적음, 긴 우회 |
| 정비 항로 | 기능 복구 | MTRL 소비, 다른 보상 빈약 |

중요 규칙:

**안전하면서 짧고 보급도 많은 항로 금지.**

그 조합이 나오면 나머지 출구가 가짜 선택이 된다.

## 5. 현재 자원이 특별히 잘 맞는 이유

이 게임은 노획량이 적함의 **실제 파괴 상태**에서 나온다.

- PROP 필요 → 연료탱크를 터뜨리면 안 된다
- MUN 필요 → 탄약고를 유폭시키면 안 된다
- MTRL 필요 → 선체를 산산조각 내면 안 된다
- RSCH 필요 → 위험한 신형 함선을 상대해야 한다

따라서 정보가 항로 선택에서 끝나지 않는다.

```
수송선 존재 확인 → 탄약 필요 판단 → 위험 항로 선택
→ 엔진과 승무원만 무력화 → 탄약고 보존 → MUN 회수
```

이 흐름이 SUPERRADIANCE 고유의 재미다.

## 6. 자원 추가 판단

지금은 추가하지 않는 편이 좋다. 새 자원이 들어올 조건 셋:

1. 물리적 원천이 있어야 한다
2. 보존하려면 **다른 사격법**이 필요해야 한다
3. 기존 자원과 다른 행동에 소비돼야 한다

예를 들어 "전자부품"을 추가하려면 센서 모듈을 온전히 노획하고, 액티브 스캔·추격 교란·중계기 복구에 써야 한다. 단순 상점 화폐라면 불필요하다. 현재는 RSCH로 충분히 대체 가능하다.

## 7. 한 판 예시

상태: 탄약 18%, 좌현 엔진 손상, 추진제 45%, 추격 도착까지 약 60초.

도착 정보 — A: 적 많음, 보급 불명. B: 적 적음, 엄폐 밀집.

플레이어가 교전 흔적으로 우회해 항법 기록을 회수한다 — A: 수송선 활동. B: 보급 희박.

선택: B로 안전하게 가면 다음 장에서 탄약 고갈 위험. A로 가면 지금 손상될 위험이 있지만 탄약 확보 가능.

A 선택. 운석 뒤로 접근. 부스터 절제. 수송선 엔진만 파괴. 탄약고 보존. MUN 회수. 출구 도착.

이때 탐험 이유, 항로 결정, 은폐 이동, 조준, 파괴 시뮬레이션, 장기 손상이 한 줄로 연결된다.

## 8. 구현 순서

1. 현재 "비전투 장소 하나 방문하면 정보 전부 공개"를 프로토타입으로 **플레이**
2. 선택이 너무 쉽게 끝나면 정보 3축 분리(§3)
3. 항로 유형 4~6개를 JSON 템플릿화(§4)
4. 생성 시 두 항로가 서로 다른 장단점을 갖도록 검증
5. 적 수송선의 탱크·탄약고 보존 노획을 핵심 보상으로 강화
6. 이후에도 선택이 부족할 때만 새 자원 검토

판정 지표:

- 정보 얻으러 직선 항로를 벗어난 비율
- 정보 확인 후 출구 선택을 바꾼 비율
- 현재 부족 자원과 선택 항로의 상관관계
- 노획 목표에 따라 조준 부위가 달라진 비율
- 특정 항로 선택률 70% 초과 여부

### 제일 먼저 걸리는 것

§8-1은 **플레이**인데 지표가 하나도 없어서 "선택이 너무 쉽게 끝나는지"를 눈으로 판단해야 한다.
`FieldLog`(측정 전용)가 그 다섯을 자동으로 적는다 - §8-1을 숫자로 끝내려고 먼저 지었다.

§4의 "거리 차이"는 설계 자체가 지금 구조와 부딪힌다. 두 출구가 같은 x에 있으면 "긴 우회"라는 비용을 만들 자리가 없다.
출구 하나를 -X 쪽이나 옆면으로 옮기든지, 거리 대신 다른 비용(점프 앵커 수, 엄폐 없음)으로 대체해야 한다. 오너 결정 사항.
